# 项目改进方案

**项目：** 错了吗（zero-defect）  
**评审基线：** `v1.0.3`（`5d28c16`）  
**编制日期：** 2026 年 11 月 19 日  
**文档状态：** 待评审。后续版本号、复习间隔和试点门槛均为建议，不是发布承诺或已取得的结果。

## 1. 决策摘要

「错了吗」已经能从试卷提取错题，按「知识点 × 错因」出变式题，并在 `v1.0.3` 加入可选的引导式订正和独立复测。下一步不必增加通用 AI 聊天入口；更值得投入的是让系统**准确区分孩子是没做、不会、答错，还是遇到了坏题**，再据此安排少量跨日复习。

| 阶段              | 建议版本 | 首要交付                                                   | 进入下一阶段的条件                                             |
| ----------------- | -------- | ---------------------------------------------------------- | -------------------------------------------------------------- |
| P0 学情可信       | `v1.0.4` | 区分作答状态；低置信归因不混入批量确认；坏题可作废且能重算 | 历史库迁移通过；订正、掌握和复测口径一致                       |
| P1 持续巩固       | `v1.1`   | 智能练习后台每日选题；到期续排；跨日无提示复测             | 用模拟时间验证排程，且小规模试点未出现积压或重复刷题           |
| P2 出题质量与速度 | `v1.2`   | 三类可计算模板；可信题可先开始；AI 保留开放变式            | 模板答案与解析同源、经过交叉校验；首题等待和题目质量有数据可比 |
| P3 家长周报       | `v1.3`   | 本机循证周报；显示依据、样本不足和下一步                   | 周报数据可回溯，且家长能读懂结果与局限                         |

**建议本次立项只批准 P0。** P1 可以先画交互原型，但先不要让新排程依赖旧的混合口径。P2 的离线题库可以独立准备；P3 不应先于跨日独立复测数据。暂不做全科扩张、自由聊天、排名、商业化学习评分或默认上传学习数据。

## 3. P0 学情可信

### 3.1 分开记作答结果与教学决策

保留第一次提交原始记录，增加或派生明确的作答状态。判分、复测和报告都使用同一套服务端判定口径，不让前端自行把空答案换算成错误。`v1.0.4` 保留「连续独立答对 3 次且跨至少 2 个日历日」这条掌握规则，只修正哪些事件能参与计算。

| 情况               | 孩子看到的结果     | 掌握度处理                                                 | 后续处理                           |
| ------------------ | ------------------ | ---------------------------------------------------------- | ---------------------------------- |
| 独立答对           | 答对               | 计入连对；符合条件可成为复测成功证据                       | 按现有规则继续                     |
| 独立答错           | 答错，可进入订正   | 打断连对；符合条件时记录为复测未通过                       | 进入薄弱项队列                     |
| 主动点「这题不会」 | 不会，可进入订正   | 不计为独立答对或答错，不清零；与「已掌握」并存时标记待复测 | 提高同类新题的复练优先级           |
| 留空、跳过或未提交 | 未作答             | 不计分、不清零，不算独立复测；未提交不补造作答             | 已到期的复测仍待完成               |
| 看提示或解析后重做 | 订正完成           | 不计入独立证据，不改变首次结果                             | 保留 `v1.0.3` 的同类变式复测入口   |
| 题目经人工确认有误 | 该题不计；说明原因 | 该题所有相关证据不再参与派生统计，不删除历史               | 重算受影响项；必要时补一道合格变式 |

**界面规则。** 「这题不会」与「跳过」分开；选择后还能返回并改成真实答案，以提交时的最终状态为准。结果页单列答对、答错、不会、未作答，合计与有效题数一致；订正默认列出答错和明确不会，留空题可以主动重做，不强迫订正。沿用「给我一点提示」和「看解析」，不把新提示放到独立首答之前。

**历史处理。** 可靠识别出的旧 `skipped` 回算为未作答；确有原始答案且能确认首答的记录保留其判分。无法确认独立作答的旧记录标为「历史状态不明」，不推断成主动不会，也不用于增减掌握度。已完成练习、原始答案、提示时间与旧试卷原图不删除。上线说明告知家长：「未作答不再扣减掌握度，部分历史统计因此会更新。」

**错题证据的口径。** 用于掌握度的卷面错题证据必须已经确认，错因不是「未作答」，有孩子作答或解题过程，且学生答案未被归一化判定为与标准答案相同。`v1.0.4` 将卷面错题证据限于当前年级与学期；学期未记录的错题随年级计入。切换年级或学期不删除历史，切回后仍会计入。独立练习证据仍按「知识点 × 错因」汇总，不按年级和学期切分。

**证据时间。** 卷面错题取第一次构成有效证据的确认时刻，旧库迁移取该条错题最后更新时间，不用原卷日期；只要仍构成证据，改错因或补充文字不重置该时间。若编辑后不再构成证据（例如答案改为与标准答案一致），时间清空。确认时间只决定这条卷面证据何时打断连对，不算独立答对的日期；「跨至少两天」只看独立答对的练习日。以上变化须写入发布说明。

### 3.2 低置信归因走局部人工复核

在 Rust 后端集中计算「能否快速确认」，返回结构化原因码。新版草稿直接使用结构化的清晰度与置信度字段；旧草稿缺少清晰度字段时，才用历史中文警告识别已知模糊记录。旧版可能将缺失或越界的置信度保存为 `0` 或 `1`，无法追溯来源的边界值走人工复核；系统生成的明确卷面留白判定仍按原规则处理。复用 `confidence_threshold`；模型自报置信度只用于分流，不能解释成实际正确概率。

- 归因低置信、关键信息缺失、识别不清、题目不完整或知识点未知：进入「需复核」。批量操作只确认通过检查的条目，结果列出确认和跳过数量及原因。快速单题确认走同样的检查；详情页人工补齐并确认后才生效。
- 把「识别到卷面留白」与「判断孩子不会」分开。留白可保存在错题库作为待练线索，不直接当成掌握退步的证据；没有解题过程时，不推断具体的思维错误。
- 复核页把相关原卷页、识别题干、学生答案、推荐错因及可核对的依据放在一起。首版沿用现有页图，不引入题目自动裁剪。修改错因后按新组合安排练习；既有练习仍归属于其出题时的组合，不静默改写历史。

### 3.3 坏题可申报、可停用、可追溯

在练习与解析处提供「题目有问题」，预设「题干或配图不清」「答案或判分不对」「解析有误」「其他」。同一道题（同一题目 ID）的重复申报合并为一条；申报对孩子没有惩罚，但**仅申报不自动改分**。作废按题目 ID 生效；生成新题时，仅排除去掉空白后的题干和配图都与作废题相同的候选。其他会话已经分发的题目不会被一并作废，需要分别申报；首版不做跨会话的文本合并。

首版用本机家长复核替代客服工单。状态为「待核对 → 确认作废／核对后保留」。确认作废后，保留原题和判定理由，把该题从后续题库及证据投影中排除，并让受影响组合的主练习统计、掌握度、复测结果在刷新后保持一致。恢复必须是明确操作并触发重算。首版不做账号身份验证，因此「家长复核」是界面分区，不是安全权限。

**P0 验收。** 对「第一天：答对、留空；第二天：再独立答对两道同类题」的固定序列，第三次独立答对后应达到掌握，旧记录仍存在。明确不会应安排复练但不增加独立错误数；低置信条目批量确认后仍待复核；同一道坏题作废两次不会重复扣减。首次复测题作废后，系统取下一条仍合格的独立作答，否则恢复待复测。展示结果与后端投影一致。

## 4. P1 智能练习的今日推荐与跨日复习

### 4.1 同一入口：今日推荐与额外练习

保留「智能练习」为默认首页和唯一练习入口。首页展示练习介绍和学习概况，不单独展示「今日 5 分钟」、复习日程或复测统计。P1 的每日推荐与跨日排程在后台运行，沿用现有出题、答题、判分和订正流程。

- **开始前。** 统一使用「开始练习」入口，由系统自动安排本轮内容。作答中不标出哪道是复测题，也不展示上次的答案。
- **进行中。** 有未结束的练习时，优先显示「继续练习」，恢复原会话而不重新出题；也可明确放弃。放弃不把未答题判错，也不清除待复习项。
- **提交后。** 同一本地日内，如有合适的内容，用户可通过「开始练习」再练一组，不重置今日状态。跳过的到期项仍留在队列中。
- **候选不足。** 没有到期内容时仍可巩固薄弱项；没有合适候选则提示暂时没有需要练习的内容，不用旧题凑数。逾期项目继续参与后台选题，不补发强制任务。

**每轮配额。** 默认最多 5 道题，可在设置中调整为 1–10 道，已开始的练习不变。到期旧项优先留最多 2 个名额，再优先安排最多 1 个已到跨日窗口的引导后复测组合，其余由近期薄弱项补位；某类候选不足时，可从其他合格候选中补位，不为凑满设定数量而重复出题。同一道题在一轮内只出现一次；若同时符合多种练习目的，题数只计一次。

### 4.2 可测试的续排规则

调度单位沿用「知识点 × 错因」。掌握判定与复习计划是两个概念：显示已掌握不代表永远不用复习；逾期也不等于遗忘。

| 有效事件                       | 排程建议                                                                                             |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 首次达到掌握                   | 第一次常规复习到期日为掌握后第 7 个本地日历日，尽量延续已有体验                                      |
| 到期复习独立答对               | 从实际作答日续排，后续间隔试用 14、30 天；达到上限后继续以 30 天为周期                               |
| 有效到期复习答错               | 回到巩固队列，次日本地日期安排一题短间隔复练；再次达到掌握后从首档重新开始                           |
| 非到期复习的独立作答答错       | 清除旧复习档位，回到巩固队列，不安排次日短间隔复练；再次达到掌握后从首档重新开始                     |
| 未作答、看提示后订正或题目作废 | 不延长间隔；作废按有效事件重新投影，未答维持待复测                                                   |
| 打开了引导提示                 | 安排一题同组合、不同题目的复测；同日可以练，但不算跨日保持。尽量在下一本地日或之后安排一题无提示测量 |

上述天数只用于首轮试点。还需验证不同难度、积压量和使用频率下的效果，避免把一套间隔当成所有学龄段的固定标准。实现上保存 UTC 事件时间，并用可注入的时钟与本地日期计算到期。今日推荐与额外练习共用一套到期队列和作答记录：只有符合到期复习条件的独立首答才会推进复习档位或触发次日短间隔复练；不符合条件的独立答错只重置掌握度和旧档位。判断不以从哪个按钮开练为准。同一组合一天最多推进一个复习档位；同日的引导后复练不结清跨日复测。跨时区不回写历史日期，用后续事件更新本地到期日。

**迁移和验收。** 旧库根据有效独立作答初始化调度；历史不足的已掌握项按保守的新起点排一次，不把所有旧项在升级当天标成必须完成。首版不引入系统提醒或云推送。

- **入口与选题：** 不新增导航；开始、继续、放弃和提交后再练均走同一练习页。验证到期名额、跨日复测优先上限、候选不足、同题去重，以及无到期但有薄弱项时仍可开练。
- **时钟与状态：** 用模拟时钟验证跨午夜、逾期、休眠重启和同日双提交；跨日继续原会话不重新出题，恢复或重提同一会话不重复推进。额外练习不重置今日状态。
- **作答与续排：** 验证未答、放弃和作废不会误结清；到期独立答错按规则回退；同日引导后复练不替代跨日测量；额外练习中的合格到期作答能更新同一队列，避免该项按原到期日再次出现。

## 5. P2 题目质量与即时练习

先覆盖有余数除法、进退位竖式和常见单位换算。每种模板从受约束的参数生成题干，由 Rust 同源产出答案和步骤，通过独立的测试预言机或手算样例交叉核验。AI 继续生成非结构化应用题与新情境；模型不可用时，只提供覆盖当前知识点的可核验模板，不把随便一道题冒充为针对性复测。

- **题目契约。** 记录生成来源、模板版本、可复现种子及题型参数；渲染前验证适龄范围、条件充分性、单位、唯一解和选项互异。应用题独立验答只证明最终结果一致；对解析、教材范围和错因相关性做抽检，不把模型共识当成真值。
- **开练速度。** 沿用「开始练习」和「继续练习」。本轮有匹配的本地题或预先验过的题时即可开练，题数遵循设置的上限，合适的题不足时可以少做。配置了 AI 服务时，后台优先为缺题的第一个练习组合准备变式供下一轮使用。若巩固练习全由本地题组成，也可以预备一道新的 AI 变式。本轮题目在开始时确定。没有合适题目时沿用在线出题，失败后可重试。
- **覆盖边界。** 本地题按教材范围、知识点、错因和难度匹配。新题记录题目结构。跨日复测以订正原题为准，出题和统计采用同一套要求。应用题需要有带数量条件的情境，并询问情境中的未知量。图题需要引用已验证的同类配图。跨日继续和历史重算同样校验。旧题可依据题干和原配图确认结构，无法确认时该复测保持待完成，作答仍按原规则判分。
- **新题去重。** 本地模板对参数和等价表达生成指纹；AI 题结合题干、答案类型与配图做规范化对比，并抽检只改表面数字或措辞的近重复。第一版不宣称能自动证明语义不同。抽样时分开报告两类来源的坏题率。
- **验收。** 每类模板覆盖边界、随机种子重放及至少一组人工标注样例。断网或超时且有匹配模板时可开始并完成短练；没有匹配时不能误报复测完成。按「点击开始 → 第一题可交互」统计 P50/P90，并单列失败率，避免只汇报成功请求的速度。

开发版可用 `window.api.getPracticeStartMetrics()` 查看本机启动样本。耗时按即时开练、在线出题和继续练习分组，失败和中断另外列出。题目质量分别汇总模板题、AI 题及来源未记录的旧题，分母是已有人工结论的题数。日常申报的复核结果有选择偏差，试点须另做分层抽检再比较坏题率。

## 6. P3 本机家长周报

周报先做成应用内视图，不做邮件、公开分享或综合评分。只回答：本周出现了哪些薄弱项、有哪些独立作答证据、下一步练什么。每项显示题数、作答日期和无提示／有提示标识；家长可点回相应记录。`1/1` 仍显示「样本少」；没有跨日证据写「还没有独立复测记录」，不写「未掌握」。

> 示例：周长与面积曾混淆。本周订正时用过一次提示；随后在两个不同日期独立做了两道同类新题，答对 2 道。下次按复习计划再检查一次。

只展示当前档案的数据，不做年级排名或跨家庭对比。首版默认本机保存，不新增外发请求；现有识卷、AI 出题仍沿用原有服务边界。若以后允许导出，另行设计确认与预览，默认不带原卷图、孩子姓名、API Key、自由文本备注或完整作答轨迹；共享试点数据前另获家长同意。

**验收。** 同一组固定记录能生成可复核的周报；重复题、提示后作答及作废题不混入独立成功数；空数据和样本偏少不会生成误导结论。试点访谈里请家长复述「孩子目前会了什么、还需要验证什么」，而不是只问页面好不好看。

## 7. 技术实施与上线检查

| 工作包              | 建议落点                                               | 验收产物                                                               |
| ------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| P0-A 作答与证据规则 | `practice.rs`、`mastery.rs`、共享 IPC 类型、练习结果页 | 同一组作答状态在提交、掌握、复测和结果展示中含义一致；覆盖旧库数据     |
| P0-B 批量复核       | `repo.rs`、`ai.rs`、错题库和确认面板                   | 明确容量和阈值边界；缺失置信度或关键证据时不默认通过；手动确认保留原因 |
| P0-C 坏题作废       | 题目状态、审计记录、统计投影、解析页                   | 状态流转幂等；一次复核可重算；历史仍能查看，作废题不会再被分配         |
| P1 今日推荐与排程   | Rust 排程模块、SQLite 到期投影、现有智能练习页         | 今日推荐与额外练习共用到期队列；模拟时钟、会话恢复和重复提交测试通过   |
| P2 题目源与 P3 周报 | 模板与校验模块、本机题目元数据、周报页面               | 样例集、抽检记录、耗时统计和周报口径测试                               |

**数据原则。** 原始作答、订正事件和题目复核决定保留，派生的掌握度、排程和周报可以重建。建议以共享的 Rust 证据筛选规则处理「首答、是否有辅助、题目版本是否有效」，避免每个页面分别从 `is_correct` 推断。SQLite 迁移采用加字段或新表、备份与完整性检查；不重写卷面图片，不静默改写作答事实。同时间的事件用稳定次序处理，重放结果一致。定规则时写清「改错因」「删除原错题」「更正题干」是否等同于新的学习证据，不用普通编辑时间替代作答时间。

**提测顺序。** 先建固定的学习事件夹具和预期投影，再做后端与迁移，最后改 UI。分别验证新库、`v1.0.3` 升级库、项目已支持的旧库导入、失败回滚链路。补模拟 AI 响应和桌面冒烟覆盖；不能在真实学习数据库上直接清洗或演练回滚。

**发布门槛。** 前端类型检查和测试、Rust 锁定依赖测试、迁移与桌面冒烟均通过；全仓检查有既有问题时，单独记录且不得引入新告警。按仓库发布手册同步版本号，在 macOS 和 Windows 验证安装、旧库升级与关键路径；用副本演练备份恢复。旧程序不能直接打开新版数据库时，不引导用户随手降级覆盖原库；回滚路径应保留升级后的作答副本，并明确旧备份恢复可能损失哪些新记录。

## 8. 效果验证与决策标准

### 8.1 指标口径

| 指标               | 定义或分母                                                                                              | 用途                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 隔天独立变式首答率 | 预先选定的第 1–3 天窗口内，实际完成的合格独立首答中答对的比例；每位学生每个组合每个窗口只取首个合格结果 | 观察短期迁移；另报应测数、未测数和复测完成率           |
| 隔周独立变式首答率 | 同口径，在第 6–9 天窗口取首次合格结果；窗口按本地日历日，从首轮订正或试点分组日算起                     | 观察保持；与同日表现分开展示                           |
| 复测完成率         | 完成合格首答的应复测项目数 ÷ 窗口内所有应复测项目数                                                     | 排查「只剩较积极的家庭作答」造成的偏差                 |
| 归因与题目质量     | 分层抽检题数、归因修正率、坏题确认率；至少区分模型题／模板题和常见题型                                  | 校准复核策略；同时报告样本数，申报率不能代替真实坏题率 |
| 可用性护栏         | 首题可交互耗时、开始失败率、练习中断率与家长确认耗时                                                    | 判断学习功能是否增加不必要的等待或操作负担             |

合格独立首答要求：不同于原题，知识点与错因相同，难度可比，无该题提示或答案预先曝光，首次有效提交且题目未作废。一道原题所获的提示不使后续新题失格。分别报告未到期、未测、跳过和作废的数量，**不把没测当答错，也不把没测从试点报告里隐藏**。

### 8.2 小规模试点

1. **先建基线。** 用固定、经人工审核的题组验证 P0 是否避免错分；记录 `v1.0.3` 和试点版的口径差异，不把算法修正导致的掌握数量变化解读为学习提升。
2. **再验证体验。** 邀请少量自愿家庭，运行约两周，观察能否复核低置信错题、在智能练习内完成「今日 5 分钟」、理解复测结果，以及能否区分今日练习和自愿加练。每周核对缺失、坏题和等待时间，先修影响判分或使用的故障。
3. **最后验证增益。** 自选提示的孩子可能本来就更需要帮助，不能直接用「看过提示」和「没看提示」两组的差值证明效果。若具备条件，在家长同意后按家庭随机比较不同提示邀请方式或复习节奏。每次只改变一个因素，保持练习材料、复测难度及测量窗口可比；为短期与隔周测量使用不同题目，记录期间额外练习。按最初分组汇报并列出退出。样本不足时，只报告方向和个案，不作效果宣传。

**继续、调整或暂停。** P0 的硬门槛是历史可恢复、关键规则可重复验证、没有已知的严重判分或数据丢失问题。后续版本先用试点基线定可用性和完成率门槛，再评估改善；若独立成绩表面上升但完成率明显降低，不视为成功。若模板错题、排程积压或复核负担明显上升，先暂停扩大覆盖，定位题型与流程原因。

## 9. 风险与近期行动

| 风险                               | 应对                                                               |
| ---------------------------------- | ------------------------------------------------------------------ |
| 学情变动被误解成孩子突然退步或进步 | 发布说明解释口径变化；在测试报告中对比新旧投影，不混合成同一趋势线 |
| 低置信队列变长，家长反而懒得确认   | 提供原因与原题页并排复核；统计确认耗时及跳过原因，抽检后再校准阈值 |
| 一次坏题确认连带隐藏大量历史       | 作废限定到具体题目及其证据，保留原始记录，支持撤销和定向重算       |
| 到期项目挤掉近期弱项               | 每轮限量、预留旧题与新练名额，积压时仍可在短时间完成一轮           |
| 把软件指标当成教学定论             | 提示与独立作答分开、显式显示样本与缺失；小试点不作因果宣传         |

**建议现在执行的顺序：** 先确认 P0 的三项数据决策（留空不降级、低置信不批量通过、坏题确认后撤回证据），再据此拆成「事件与迁移」「错题复核」「坏题处置」三个可单独验收的工作项。发布 P0 后，带着第一批真实的错题复核负担和复测完成数据，决定 P1 的配额与默认间隔。
