# 小学生错题针对性训练系统

## 1. 文档目的

本文档将产品需求收敛为一套可执行的技术设计，目标是支持以下闭环：

```text
拍照上传错题
  → AI 识别题目和学生解题过程
  → AI 给出错误归因候选
  → 家长确认或修改归因
  → 系统保存错题与掌握度
  → AI 生成针对归因的变式题
  → 孩子作答
  → 系统判题并更新复习权重
```

本项目是个人家庭使用的本地桌面应用，界面保持简单，复杂度集中在内部的 AI 分析、题目生成、校验和掌握度计算。

### 1.1 文档定位

- 本文档是实现的唯一依据。`requirement.md` 只保留产品意图，其中的掌握度规则、归因标签、表结构和模型名称均以本文档为准。
- 模型 ID 不写死。视觉模型和文本模型分别配置，开工前需在 OpenRouter 模型列表核对可用性、价格和数据留存策略。
- 命名约定：项目代号、仓库名和包名使用 **Zero Defect** / `zero-defect`；界面上显示的应用名是 **超级错题本**，不带英文名和副标题。应用显示名集中放在 `src/shared/app-info.ts` 的常量里（窗口标题、首页标题引用它；打包的 `productName` 与它保持一致），不在界面里散写。
- 本版相对上一版的主要变化：新增阶段零验证实验；错题与归因改为多对多；掌握度按“归因 + 知识点”计分；变式题校验改为可执行方案；题目改为预生成题池；IPC 改为句柄方式；补充 API Key 与隐私要求。

## 2. 目标与范围

### 2.1 MVP 目标

- 支持从本地选择或粘贴错题图片。
- 识别题目、学生答案、解题过程、知识点和错误归因候选。
- 允许家长确认或修改 AI 结果。
- 将错题和归因保存到本地 SQLite。
- 根据未掌握的错误归因生成每日 3 道左右的变式题。
- 支持孩子直接输入答案并自动判题。
- 根据答题结果调整错误归因的练习权重。
- 支持普通文字、Markdown 和数学公式显示。

### 2.2 MVP 暂不包含

- 登录、多用户、多孩子管理。
- 云端同步和服务器数据库。
- 社交、排行榜和复杂游戏化系统。
- 自动识别孩子每一次手写练习答案。
- 自动处理所有复杂几何图形。
- 完全无人确认的错误归因。

手写答案拍照识别、复杂几何题和更自动化的归因，可以在 MVP 验证后增加。

## 3. 产品界面

界面只保留两个主要入口。

### 3.1 首页

首页显示：

- 今日待练习题数量。
- 当前未掌握的错误归因数量。
- “上传错题”按钮。
- “开始每日练习”按钮。
- 最近上传的错题和最近一次练习结果。

### 3.2 上传错题流程

1. 用户选择图片或粘贴截图。
2. 页面显示图片预览和识别进度。
3. 主进程调用 AI 服务。
4. 页面展示 AI 识别结果：
   - 题目内容
   - 学生答案
   - 学生解题过程
   - 知识点
   - 错误归因候选
5. 家长确认、修改或跳过归因。
6. 系统保存错题、原始图片和 AI 分析结果。

补充规则：

- 图片选择和粘贴截图都由主进程接收，处理后放入应用临时目录，渲染进程只拿到图片句柄（`imageId`），不接触文件路径。分析成功、写入草稿错题时，图片才移入正式图片目录。
- 家长放弃草稿（`discardDraft`）时，同时删除草稿记录和图片，使同一张图片之后可以重新上传。
- 导入图片时计算内容哈希，已存在相同哈希的错题时提示“这张图已上传过”，避免重复数据。
- AI 分析完成后立即写入 `status = 'draft'` 的错题记录。家长确认前应用崩溃，重启后可从草稿继续，不必重新调用 AI。
- 家长选择“跳过归因”时，错题保存为 `status = 'unattributed'`，`mistake_root_causes` 不写入记录，不进入练习调度。之后可在错题本里补充归因。
- 题目文本、学生答案、标准答案在确认页均可编辑。识别出的标准答案可能有误，家长需要核对。

如果照片只有题目和最终答案，系统可以识别题目，但错误归因的置信度通常较低。因此上传时应尽量包含完整解题过程、批改痕迹或标准答案。

### 3.3 每日练习流程

1. 系统按照当前“归因 + 知识点”权重选择需要练习的条目。
2. 从已校验的题池中取题；题池不足时才临时生成。
3. 一次显示一道题。
4. 孩子输入答案。
5. 系统判题并显示正确答案、解析和错误原因。
6. 更新对应归因的掌握度。
7. 进入下一题，直到完成当天练习。

题池由后台预生成：家长确认错题后，以及应用空闲时，系统按调度需要补充题目，每个“归因 + 知识点”保持 3～6 道已校验题待用。孩子点击“开始每日练习”时直接取题，不需要等待 AI 调用。

第一版优先支持整数、小数、分数、带分数、百分数和“商…余”形式的答案输入，答案可以附带单位（判题时单位单独处理，见第 11 节）。选择题和手写答案拍照上传放到之后的版本。

### 3.4 视觉风格设计

视觉方向参考用户提供的界面：使用明快的渐变色、圆角卡片、清晰的大图标和突出的主操作按钮。整体感觉应当像一个“学习小伙伴”，而不是复杂的管理工具。

设计原则：

- 首页只突出“上传错题”和“开始今日练习”两个主操作。
- 使用图标加短文字，避免长段说明和专业术语。
- 重要按钮保持大尺寸，建议最小高度 56px，方便小朋友点击。
- 卡片使用 20～28px 圆角，界面保持足够留白。
- 每个页面只保留一个主要任务，避免同时出现多个竞争性按钮。
- 识别中、答对、答错和完成练习都使用明显的颜色、图标和简短反馈。
- 错题归因等复杂信息默认折叠，家长确认时再展开。

建议的视觉语言：

```text
主色：明亮蓝紫渐变
辅助色：薄荷绿、阳光黄、珊瑚橙
背景：浅蓝或浅紫，减少大面积纯白
文字：深蓝灰，保证阅读对比度
卡片：白色或半透明浅色，带柔和阴影
```

参考图中的深色紫色背景和大面积渐变可以保留为品牌视觉，但儿童主界面建议使用更明亮的背景和更高的文字对比度。渐变用于顶部区域、主卡片和重点按钮，避免整个页面持续使用高饱和发光效果。

推荐首页布局：

```text
┌──────────────────────────────────────┐
│  超级错题本                     👋   │
│                                      │
│  ┌──────────────┐  ┌──────────────┐  │
│  │ 📷 上传错题  │  │ ⭐ 今日练习  │  │
│  │ 把不会的题交给我│ │ 还有 3 道题  │  │
│  └──────────────┘  └──────────────┘  │
│                                      │
│  今日学习进度                         │
│  ●●○○○  已完成 2 / 5                 │
│                                      │
│  最近的错题                           │
│  分数通分 · 需要再练习                │
└──────────────────────────────────────┘
```

侧边导航可以沿用参考图的图标化形式，但 MVP 只保留：

- 首页
- 上传错题
- 每日练习
- 错题本

设置、AI 调试信息、掌握度明细和数据库操作放在家长入口或设置页面，不出现在孩子的主流程中。

练习页面采用“单题聚焦”布局：上方显示进度，中间显示题目卡片，下方显示一个大的答案输入框和“提交答案”按钮。答对后使用轻量动画和鼓励语，答错后先显示提示，再显示解析，避免使用令人沮丧的红色警告样式。

## 4. 总体架构

```text
┌──────────────────────────────┐
│ React Renderer                │
│ 首页 / 上传 / 每日练习        │
│ Markdown + KaTeX + SVG 渲染  │
└──────────────┬───────────────┘
               │ 白名单 IPC
┌──────────────▼───────────────┐
│ Electron Main Process        │
│ Mistake Service              │
│ Practice Service             │
│ Mastery Service              │
│ AI Provider                  │
│ Image Storage                │
│ SQLite Repository             │
└──────────────┬───────────────┘
               │ HTTPS
┌──────────────▼───────────────┐
│ OpenRouter                   │
│ 可配置视觉/文本模型           │
└──────────────────────────────┘
```

推荐技术栈：

- Electron + TypeScript
- React + Vite
- Tailwind CSS
- `better-sqlite3`
- `react-markdown`
- `remark-math` + `rehype-katex`
- `zod` 做 AI 输出和 IPC 参数校验
- Electron Forge 或 electron-builder 打包

API 请求必须放在 Electron 主进程。渲染进程只通过白名单 IPC 调用能力，不能直接访问 SQLite、文件系统或 OpenRouter。

### 4.1 密钥与隐私

- OpenRouter API Key 由家长在设置页输入，主进程使用 Electron `safeStorage` 加密后保存，不写入代码、日志或数据库明文。
- 孩子的作业照片会发送给 OpenRouter 及上游模型厂商。导入图片时去除 EXIF 信息并压缩，上传前提示家长避免拍到姓名、学校等个人信息。
- 在 OpenRouter 设置中关闭数据用于训练，并优先选择不留存数据的模型提供方。
- `ai_runs` 不保存图片 base64，只保存图片哈希和本地路径，避免数据库膨胀。
- 渲染进程启用 `contextIsolation`，关闭 `nodeIntegration`，设置严格的 CSP。

### 4.2 原生模块打包

`better-sqlite3` 是原生模块，需要使用 `electron-rebuild`（或 Forge/electron-builder 的对应配置）针对 Electron 版本编译，打包时将其放入 asar unpack。阶段一就应跑通一次完整打包，而不是留到最后。

## 5. 内容表示与题目渲染

AI 不直接返回完整 HTML，而是返回结构化 JSON。题目正文和解析使用 Markdown，数学公式使用 LaTeX，前端最终将其渲染为 HTML。

示例：

```json
{
  "question": "小明有 24 个苹果，吃了其中的 $\\frac{1}{3}$，还剩多少个？",
  "answer": "16",
  "solution": "先求吃掉的苹果：$24 \\times \\frac{1}{3}=8$。\n\n还剩：$24-8=16$。"
}
```

渲染规则：

- 普通文本：Markdown。
- 分数、根号和公式：LaTeX + KaTeX。
- 几何图形：独立的 SVG 数据或图形描述。
- 图片：应用内部资源引用。
- AI 生成的 HTML：默认不允许直接注入。

几何题可以使用如下结构：

```json
{
  "diagram": {
    "type": "rectangle",
    "width": 8,
    "height": 5,
    "labels": ["长 8 厘米", "宽 5 厘米"]
  }
}
```

前端根据 `diagram` 绘制 SVG，避免让模型生成难以校验的 HTML 或图片。

## 6. 核心领域模型

### 6.1 错题 Mistake

一条错题记录代表原始图片、识别内容和一次或多次归因。

主要字段：

- `id`
- `image_path`、`image_hash`
- `question_markdown`
- `student_answer`
- `student_work_markdown`
- `correct_answer`
- `grade`
- `subject`
- `knowledge_point_id`
- `status`：`draft`（已分析未确认）、`active`（已确认并参与练习）、`unattributed`（跳过归因）、`archived`
- `created_at`

错题与归因是多对多关系，由 `mistake_root_causes` 关联表保存。每条关联记录包含 AI 置信度、证据、是否被家长确认。MVP 界面上每道错题只要求家长确认一个主归因，数据模型保留多归因的能力。

### 6.2 错误归因 Root Cause

归因是练习调度的核心实体。多道原题可以关联同一个归因。

MVP 示例分类：

- `carry_omission`：进位或退位遗漏
- `place_value_error`：数位对齐错误
- `calculation_error`：基础计算错误
- `operation_order_error`：运算顺序错误
- `fraction_common_denominator`：分数通分错误
- `unit_omission`：单位遗漏或单位混淆
- `reading_comprehension_error`：题意理解错误
- `formula_confusion`：公式或概念混淆

归因分类必须有限、稳定、可复用。不要让模型每次自由发明新的标签。

另有一个系统保留的归因 `needs_review`（待人工确认）。它作为种子数据写入 `root_causes`，`active = 0`，不参与练习调度，只用于承接模型返回了未知 code 的情况。

### 6.2.1 知识点 Knowledge Point

`calculation_error` 这类归因覆盖面很宽，孩子可能加法已经掌握而乘法没有。因此掌握度按“归因 + 知识点”两个维度计分。

- 知识点使用固定清单（按年级维护，如“两位数乘法”“异分母分数加法”“长方形周长”），写入 `knowledge_points` 表。
- 视觉请求中附带当前年级的知识点清单，要求模型从中选择；没有合适项时返回 `other`，由家长在确认页选择或新增。
- 调度、变式题生成约束和掌握度都以 `(root_cause_id, knowledge_point_id)` 为单位。

### 6.3 练习题 Practice Question

练习题关联一个错误归因，保存生成时使用的约束和模型结果，保证题目可以追溯。

主要字段：

- `id`
- `session_id`：题池中尚未分配到某天练习时为空
- `position`：在当天练习中的顺序
- `root_cause_id`、`knowledge_point_id`
- `question_markdown`
- `answer_type`
- `correct_answer`、`answer_unit`
- `solution_markdown`
- `difficulty`
- `source_mistake_id`
- `status`：`pool`（待用）、`assigned`（已分配到会话）、`answered`、`discarded`
- `verify_json`：校验时使用的表达式与结果
- `generation_json`
- `created_at`

### 6.4 作答记录 Answer Attempt

每次作答都必须保存，掌握度由历史记录计算或更新。

主要字段：

- `id`
- `practice_question_id`
- `root_cause_id`、`knowledge_point_id`
- `submitted_answer`、`normalized_answer`
- `is_correct`
- `used_hint`
- `answer_time_ms`
- `created_at`

## 7. SQLite 设计

```sql
CREATE TABLE root_causes (
  id TEXT PRIMARY KEY,
  code TEXT NOT NULL UNIQUE,
  label TEXT NOT NULL,
  description TEXT,
  active INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL
);

CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL
);

CREATE TABLE knowledge_points (
  id TEXT PRIMARY KEY,
  grade INTEGER NOT NULL,
  code TEXT NOT NULL UNIQUE,
  label TEXT NOT NULL,
  active INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE mistakes (
  id TEXT PRIMARY KEY,
  image_path TEXT,
  image_hash TEXT UNIQUE,
  question_markdown TEXT NOT NULL,
  student_answer TEXT,
  student_work_markdown TEXT,
  correct_answer TEXT,
  grade INTEGER,
  subject TEXT NOT NULL DEFAULT 'math',
  knowledge_point_id TEXT,
  analysis_json TEXT,
  status TEXT NOT NULL DEFAULT 'draft'
    CHECK (status IN ('draft','active','unattributed','archived')),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_points(id)
);

CREATE TABLE mistake_root_causes (
  mistake_id TEXT NOT NULL,
  root_cause_id TEXT NOT NULL,
  confidence REAL,
  evidence TEXT,
  confirmed INTEGER NOT NULL DEFAULT 0,
  is_primary INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (mistake_id, root_cause_id),
  FOREIGN KEY (mistake_id) REFERENCES mistakes(id),
  FOREIGN KEY (root_cause_id) REFERENCES root_causes(id)
);

CREATE TABLE mastery (
  root_cause_id TEXT NOT NULL,
  knowledge_point_id TEXT NOT NULL,
  score REAL NOT NULL DEFAULT 1.0,
  consecutive_correct INTEGER NOT NULL DEFAULT 0,
  review_level INTEGER NOT NULL DEFAULT 0,
  total_attempts INTEGER NOT NULL DEFAULT 0,
  correct_attempts INTEGER NOT NULL DEFAULT 0,
  last_practiced_at TEXT,
  last_wrong_at TEXT,
  next_review_at TEXT,
  status TEXT NOT NULL DEFAULT 'active'
    CHECK (status IN ('active','review')),
  PRIMARY KEY (root_cause_id, knowledge_point_id),
  FOREIGN KEY (root_cause_id) REFERENCES root_causes(id),
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_points(id)
);

CREATE TABLE practice_sessions (
  id TEXT PRIMARY KEY,
  practice_date TEXT NOT NULL UNIQUE,
  status TEXT NOT NULL DEFAULT 'pending',
  created_at TEXT NOT NULL,
  completed_at TEXT
);

CREATE TABLE practice_questions (
  id TEXT PRIMARY KEY,
  session_id TEXT,
  position INTEGER,
  root_cause_id TEXT NOT NULL,
  knowledge_point_id TEXT NOT NULL,
  source_mistake_id TEXT,
  question_markdown TEXT NOT NULL,
  answer_type TEXT NOT NULL,
  correct_answer TEXT NOT NULL,
  answer_unit TEXT,
  solution_markdown TEXT,
  difficulty INTEGER NOT NULL,
  status TEXT NOT NULL DEFAULT 'pool'
    CHECK (status IN ('pool','assigned','answered','discarded')),
  verify_json TEXT,
  generation_json TEXT,
  created_at TEXT NOT NULL,
  FOREIGN KEY (session_id) REFERENCES practice_sessions(id),
  FOREIGN KEY (root_cause_id) REFERENCES root_causes(id),
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_points(id),
  FOREIGN KEY (source_mistake_id) REFERENCES mistakes(id)
);

CREATE TABLE answer_attempts (
  id TEXT PRIMARY KEY,
  practice_question_id TEXT NOT NULL,
  root_cause_id TEXT NOT NULL,
  knowledge_point_id TEXT NOT NULL,
  submitted_answer TEXT NOT NULL,
  normalized_answer TEXT,
  is_correct INTEGER NOT NULL,
  used_hint INTEGER NOT NULL DEFAULT 0,
  answer_time_ms INTEGER,
  created_at TEXT NOT NULL,
  FOREIGN KEY (practice_question_id) REFERENCES practice_questions(id),
  FOREIGN KEY (root_cause_id) REFERENCES root_causes(id),
  FOREIGN KEY (knowledge_point_id) REFERENCES knowledge_points(id)
);

CREATE INDEX idx_attempts_question ON answer_attempts(practice_question_id);
CREATE INDEX idx_attempts_cause ON answer_attempts(root_cause_id, knowledge_point_id, created_at);
CREATE INDEX idx_questions_pool ON practice_questions(root_cause_id, knowledge_point_id, status);
CREATE INDEX idx_mistakes_status ON mistakes(status, created_at);

-- input_json 不保存图片 base64，只保存图片哈希和提示词参数
CREATE TABLE ai_runs (
  id TEXT PRIMARY KEY,
  run_type TEXT NOT NULL,
  input_json TEXT NOT NULL,
  output_json TEXT,
  model TEXT NOT NULL,
  status TEXT NOT NULL,
  error_message TEXT,
  created_at TEXT NOT NULL
);
```

图片文件放在应用数据目录下，数据库只保存路径。所有数据库修改通过 migration 管理（`schema_migrations` 记录已执行版本），不能依赖手工修改表结构。每次连接时执行 `PRAGMA foreign_keys = ON`，升级前自动备份数据库文件。

`root_causes` 的种子数据包含第 6.2 节的 8 个分类和保留项 `needs_review`；`knowledge_points` 按年级提供初始清单，并包含一条保留项 `other`（各年级通用），随 migration 一起发布。

`confirmMistake` 必须拒绝 `needs_review` 作为归因（家长要改选真实归因后才能确认），因此不会为它创建 `mastery` 记录。`other` 知识点允许确认，它是一个正常的掌握度条目。

## 8. AI 错题分析流程

### 8.1 请求内容

视觉请求包含：

- 原始图片或压缩后的图片。
- 年级和学科。
- 固定的归因分类列表。
- 当前年级的知识点清单（要求从中选择，没有合适项返回 `other`）。
- JSON Schema 或等价的结构化输出约束。

图片在主进程中缩放压缩（长边不超过约 2000px）并去除 EXIF 后再发送。

### 8.2 返回结构

```json
{
  "question_markdown": "...",
  "student_answer": "...",
  "student_work_markdown": "...",
  "correct_answer": "...",
  "knowledge_point_code": "mul_two_digit",
  "has_student_work": true,
  "image_quality": "ok",
  "root_causes": [
    {
      "code": "carry_omission",
      "confidence": 0.82,
      "evidence": "第二步加法没有包含个位产生的进位"
    }
  ],
  "recommended_root_cause": "carry_omission",
  "needs_confirmation": true
}
```

### 8.3 处理规则

- JSON 解析失败：自动重试一次，仍失败则要求人工录入。
- 模型返回未知归因：映射为 `needs_review`（种子数据，`active = 0`），不能直接进入练习调度，必须由家长改选。
- 模型返回未知知识点：映射为 `other`，由家长在确认页选择。
- `has_student_work` 为 false（只有题目和最终答案）时，归因置信度上限压低到 0.5，并在确认页提示“缺少解题过程，归因仅供参考”。
- 置信度低于阈值（默认 0.7，可配置）：强制显示确认页面；MVP 阶段所有归因都需要家长确认。
- 模型提取的 `correct_answer` 与独立求解结果不一致时，在确认页标出“标准答案存疑”。独立求解复用 9.2 第 3 步的纯文本解题请求（只给题目，不给答案），不再附带图片，成本很低；题目不是计算题或求解失败时跳过这一检查。
- 图片无法识别：提示重新拍照，不写入正式错题。
- 原始 AI 输出保存到 `ai_runs`，便于调试和重新分析。

AI 归因是候选判断，家长确认后的归因才是正式训练依据。

## 9. 变式题生成

变式题生成只发送纯文本和结构化约束，通常不需要再次发送原图。

输入约束包括：

- 年级。
- 知识点。
- 已确认的错误归因。
- 原题的抽象信息。
- 题目数量。
- 难度范围。
- 答案类型。
- 禁止超纲的知识点。

示例提示约束：

```text
年级：小学三年级
知识点：两位数乘法
错误归因：进位遗漏
生成数量：3
要求：
1. 数字和生活情境必须变化。
2. 每道题都必须包含至少一次进位。
3. 返回题目、标准答案、分步解析和难度。
4. 不使用超出三年级范围的知识。
5. 只返回约定的 JSON 结构。
```

AI 返回后必须经过本地校验。校验按题型分层，每层都有明确的通过条件。

### 9.1 返回结构增加可校验字段

每道题除题目、答案、解析、难度外，还必须返回：

```json
{
  "answer_type": "integer",
  "verify": {
    "kind": "expression",
    "expression": "24 - 24 * 1/3",
    "expected": "16"
  },
  "features": { "carry_count": 0, "borrow_count": 0, "needs_common_denominator": false }
}
```

- `verify.expression` 只允许数字、四则运算符、括号和分数，由本地解析器计算，不使用 `eval`。
- 分数和小数使用有理数库（如 `fraction.js`）计算，不使用浮点数。
- `features` 是模型自报的题目特征，本地用代码独立统计后与之比对（见 9.3）。

### 9.2 校验层级

1. **结构完整性**：题目、答案、解析、难度、`verify` 齐全，通过 `zod` 校验。
2. **表达式校验**：本地计算 `verify.expression`，结果必须等于 `correct_answer`。
3. **应用题交叉验证**：无法用单个表达式表达的题目，发起一次独立的解题请求（只给题目，不给答案），两次答案一致才通过。不一致则丢弃。
4. **选择题**（`choice` 类型为后续版本预留，MVP 的生成器不产出）：正确选项唯一，且选项之间不等价。
5. **年级与难度**：数值范围、小数位数、分母大小限制在年级配置内；题目文本与知识点清单中禁止项做关键词比对。
6. **去重**：与同一归因下近期题目的数字组合和文本相似度比对，过高则丢弃。

### 9.3 归因相关性校验

“题目是否真的考到目标归因”不使用 LLM 主观判断，而是为每个归因定义可计算的规则，由本地代码统计：

| 归因 | 本地检查 |
|---|---|
| `carry_omission` | 对题中的加法/乘法算式统计进位次数，要求至少 1 次 |
| `place_value_error` | 题中包含多位数运算且各数位数不同 |
| `fraction_common_denominator` | 涉及分数加减且分母不相等 |
| `operation_order_error` | 表达式同时含有加减与乘除，或含括号 |
| `unit_omission` | 题目或答案带单位，且存在单位换算 |

没有可计算规则的归因（如 `reading_comprehension_error`、`formula_confusion`），只做 9.2 的校验，并在 `verify_json` 中标记 `relevance_checked = false`，这类题的质量依赖家长抽查。

### 9.4 失败处理

校验失败时最多重试两次，仍失败则放弃该题并标记 `discarded`。后台补池时从其他题继续补，每日练习不能因为一条坏题阻塞整个流程。题池为空且网络不可用时，使用已有的 `answered` 题中同一归因的旧题重练（数字不变）并向家长说明。记录每次生成的通过率，用于判断模型和提示词质量。

## 10. 掌握度和练习调度

掌握度以“错误归因 + 知识点”为单位（`mastery` 表主键），不直接以某一道原题的状态代表掌握情况。

家长确认错题时：

- 对应的 `(root_cause_id, knowledge_point_id)` 还没有 `mastery` 记录，就创建一条，`score = 1.0`。
- 已有记录，说明孩子又在这个点上出了新的错。此时 `status` 回到 `active`，`review_level` 和 `consecutive_correct` 清零，`score` 至少提高到 1.0。

### 10.1 更新规则

默认参数集中放在一个配置对象里，便于后续调整：

- 答对：`score = max(0.1, score × 0.7)`；使用了提示则只乘 0.85。
- 答错：`score = min(10.0, score × 1.5)`。一次答对再一次答错，分数净变化为 ×1.05，基本持平，避免单次粗心把权重推得过高。
- 答错后 `consecutive_correct` 清零，`review_level` 回退到 0，状态回到 `active`。
- 答对后 `consecutive_correct + 1`。
- 连续答对 3 次，且这 3 次答对分布在至少 2 个不同日期，状态变为 `review`，`review_level = 1`，`next_review_at = 今天 + 3 天`。
- 单次作答耗时过短（例如小于 2 秒）且答错，视为误触，不更新权重，只记录作答。

### 10.2 复习间隔

进入 `review` 后按 `review_level` 设置下次复习时间：

| review_level | 间隔 |
|---|---|
| 1 | 3 天 |
| 2 | 7 天 |
| 3 | 14 天 |
| 4 及以上 | 30 天 |

到期复习答对则 `review_level + 1`，并按新等级重设 `next_review_at`；答错则按 10.1 回到 `active`。`review_level` 达到 4 后，该条目 `mastery.status` 保持 `review`，只按 30 天间隔出现，不会永久归档。

### 10.3 时间衰减

长时间未练习时，权重逐渐恢复，防止遗忘：

```text
time_decay = 1 + min(1.0, days_since_last_practice / 14)
```

即 14 天未练习时，优先级翻倍，不会无限增长。从未练习过的条目（`last_practiced_at` 为空）`time_decay = 1`。

### 10.4 每日选择

每天的条目选择使用优先级排序（MVP 不用随机，便于测试和复现）：

```text
recent_error_factor = 1.5   # 最近 3 天内答错过
                    = 1.0   # 其他情况
priority = score × time_decay × recent_error_factor
```

选择规则：

- `status = 'active'` 的条目全部参与排序。
- `status = 'review'` 的条目只有在 `next_review_at` 已到期时才参与，且每天最多占 1 题。
- 每天默认 3 题，家长可在设置中改为 3～5。
- 先在 `active` 条目中按优先级取前 1～3 个。只有一个 `active` 条目时，当天全部题目都出自该条目；有多个时，按优先级比例分配题数，每个入选条目至少 1 题。
- 到期的 `review` 条目最多取 1 个，占 1 题，从总题数中扣除。
- 当天只有到期的 `review` 条目、没有 `active` 条目时，当天只出这 1 道题。
- 没有任何 `active` 条目且没有到期的 `review` 条目时，首页显示“今天没有需要练习的内容”，不强行出题。
- 若只剩 `review` 条目但尚未到期，不展示它们，这与第 15 节的验收标准一致。

不要因为一次答对就将条目永久归档，必须经过连续答对和延迟复习。

### 10.5 样本量说明

每天只有约 3 道题，单个条目的样本很少，一次粗心就会显著影响权重。因此：

- 答对和答错使用不对称系数，答错惩罚较轻（见 10.1）。
- 连续答对 3 次的要求分布在至少 2 个不同日期，避免同一天的偶然答对就进入复习。
- 家长可以在掌握度明细页手动调整某个条目的权重或状态（阶段三提供）。

## 11. 判题规则

第一版支持结构化答案类型：

- `integer`
- `decimal`
- `fraction`
- `mixed_number`：带分数，如 `1又1/2`
- `quotient_remainder`：如 `7...3`
- `percent`
- `text`
- `choice`

答案判定流程：

1. 去除前后空格。
2. 统一全角和半角字符。
3. 统一乘号、除号、负号、省略号（`…`、`...`、`……`）和“又”“余”等写法。
4. 如果答案带单位，拆分为数值部分和单位部分。
5. 数字答案转换为有理数对象（不使用浮点数）。
6. 分数约分后比较；带分数先转换为假分数再比较。
7. 小数与分数是否等价由题目的 `answer_type` 决定：要求分数的题目，只接受分数形式；要求小数的题目，只接受小数形式。
8. 文本答案采用选项或标准答案匹配。

单位规则：

- 题目 `answer_unit` 不为空时，数值正确但单位缺失，判为答对，同时在反馈里提示补单位。这次作答按“使用了提示”处理，掌握度只乘 0.85（见 10.1），不另设统计口径。
- 数值正确但单位写错（如 cm 写成 m），判为错误。
- 单位匹配允许常见写法（如“厘米”“cm”），由一张本地单位同义词表处理。

“解题过程是否正确”不放在 MVP 的自动判题范围内。孩子输入最终答案即可，解析由系统展示。

## 12. IPC 接口

建议只暴露明确的领域接口：

```ts
type Api = {
  // 图片：主进程接收文件或剪贴板数据并落盘，只返回句柄和预览
  pickImage(): Promise<{ imageId: string; previewDataUrl: string } | null>;
  pasteImage(): Promise<{ imageId: string; previewDataUrl: string } | null>;

  // 错题分析与确认
  analyzeMistake(input: { imageId: string }): Promise<AnalysisResult>;
  retryAnalysis(input: { mistakeId: string }): Promise<AnalysisResult>;
  confirmMistake(input: ConfirmMistakeInput): Promise<Mistake>;
  skipAttribution(input: { mistakeId: string }): Promise<Mistake>;
  discardDraft(input: { mistakeId: string }): Promise<void>;
  listMistakes(input?: { status?: MistakeStatus }): Promise<MistakeSummary[]>;
  getMistake(id: string): Promise<MistakeDetail>;
  updateMistake(input: UpdateMistakeInput): Promise<Mistake>;

  // 首页与练习
  getHomeSummary(): Promise<HomeSummary>; // 今日题数、未掌握条目数、最近错题和练习结果
  getTodaySession(): Promise<PracticeSession | null>;
  createTodaySession(): Promise<PracticeSession>;
  getPracticeQuestion(id: string): Promise<PracticeQuestion>;
  submitAnswer(input: SubmitAnswerInput): Promise<AnswerResult>;

  // 家长入口
  getMasterySummary(): Promise<MasteryItem[]>;
  getSettings(): Promise<Settings>;
  saveSettings(input: SettingsInput): Promise<void>;
  setApiKey(input: { key: string }): Promise<void>; // 只写，不提供读取
  verifyParentGate(input: { answer: string }): Promise<boolean>;
};
```

接口设计原则：

- 渲染进程从不传递文件路径，只传 `imageId`、`mistakeId` 这类句柄，由主进程查表得到真实路径。
- 所有入参在主进程用 `zod` 校验。
- `setApiKey` 只写不读，渲染进程拿不到密钥。
- 家长入口的 `verifyParentGate` 只是简单的成人验证（如回答一道算术题），目的是防止孩子误入设置页，不作为安全边界。
- Renderer 不应获得任意 SQL、任意文件路径读取或任意 URL 请求能力。

## 13. 失败处理和可恢复性

AI 调用可能超时、限流或返回无效内容，因此需要：

- 请求超时控制。
- 指数退避重试。
- 当前任务状态持久化。
- 失败后允许重新执行。
- 生成每日练习失败时保留已有题目。
- 网络不可用时显示可理解的错误信息。
- SQLite 写入使用事务。

上传分析流程建议使用状态机：

```text
selected
→ analyzing
→ analyzed      （写入 status = 'draft' 的错题）
→ confirmed     （家长确认，status = 'active'）
→ saved
```

任一步失败进入 `failed`，并记录原因（写入 `ai_runs`），允许从失败点重试。`selected` 和 `analyzing` 阶段还没有错题记录，状态只保存在主进程内存和临时图片上，应用重启后需要重新选择图片；`analyzed` 之后的草稿已入库，重启后可继续确认。图片哈希去重避免用户重复上传造成重复数据。

题池补充任务同样持久化：记录每个 `(归因, 知识点)` 的目标题数和已有题数，应用启动和空闲时检查并补足，失败时按指数退避重试，不影响孩子正在进行的练习。

## 14. 开发阶段

### 阶段零：识别验证实验（开工前）

用不超过一周验证最大的未知风险，不写正式应用代码，只用脚本调用候选视觉模型：

- 收集约 20 张真实错题照片，覆盖印刷体、手写体、有无批改痕迹、含简单图形的题。
- 衡量：题干识别准确率、学生答案和解题过程识别准确率、标准答案正确率、家长认可的归因比例。
- 同时验证第 9 节的变式题校验通过率（生成 30 道题，统计通过校验的比例）。
- 通过标准（建议）：题干识别准确率不低于 90%，家长认可的主归因不低于 60%，变式题校验通过率不低于 70%。不达标则先调整提示词或换模型，再进入阶段一。
- 核对模型 ID、价格和数据留存策略。

### 阶段一：基础闭环

- Electron 项目初始化，并跑通一次含 `better-sqlite3` 的完整打包。
- SQLite migration，包含 `root_causes`、`knowledge_points`、`mastery` 等全部基础表和种子数据。
- 图片选择、粘贴、压缩、去 EXIF、哈希去重和本地存储。
- 上传页面和确认页面，Markdown + KaTeX 渲染。
- AI 识别接口、`ai_runs` 记录、API Key 的 `safeStorage` 存储。
- 草稿保存和错题保存。

### 阶段二：每日练习

- 变式题生成与第 9 节的本地校验。
- 题池预生成与补充任务。
- 掌握度更新与每日调度（第 10 节）。
- 每日练习页面。
- 第 11 节的判题规则。

### 阶段三：稳定性和体验

- AI 失败重试与网络错误提示。
- 历史错题查看与补充归因。
- 家长入口：掌握度明细、手动调整权重、设置页。
- 题目生成质量记录（校验通过率、丢弃原因）。
- 数据库备份与升级。
- 应用打包与签名。

### 阶段四：增强功能

- 拍照上传练习答案。
- 手写过程分析。
- 几何题 SVG。
- 更多错误归因。
- 选择题和单位答案的专项练习。

## 15. 验收标准

MVP 完成时，应满足：

- 可以上传一张错题照片并得到结构化识别结果。
- 家长可以修改题目文本和错误归因。
- 错题可以在应用重启后继续查看。
- 系统可以生成至少 3 道与归因相关的变式题。
- 生成题目有可验证的标准答案。
- 孩子输入正确答案后，系统判定正确并降低对应权重。
- 孩子输入错误答案后，系统判定错误并提高对应权重。
- 处于 `review` 状态的条目只在 `next_review_at` 到期后出现，每天最多 1 题；没有可练习内容时首页显示提示，不强行出题。
- 数学公式可以正确显示。
- AI 失败时不会丢失已经保存的错题；确认页崩溃后可从草稿恢复。
- 重复上传同一张图片时，系统提示已存在，不产生重复记录。
- 点击“开始每日练习”时，题池充足的情况下无需等待 AI 调用即可显示第一题。
- 判题支持整数、小数、分数、带分数、商余数和带单位答案。
- 打包后的应用在全新 macOS 环境中可以启动，并能读写 SQLite。
- API Key 不出现在代码、日志和数据库明文中。

质量指标（阶段零和阶段二各测一次，记录结果）：

- 题干识别准确率、家长认可的主归因比例，以及变式题校验通过率，达到阶段零设定的通过标准。

## 16. 关键设计结论

1. 界面只需要“上传错题”和“每日练习”两个主功能。
2. AI 归因采用候选结果，家长确认后才作为训练依据；未确认的分析结果以草稿保存。
3. 错误归因和知识点都必须使用固定分类，不能让模型自由生成标签。
4. 变式题生成必须经过本地答案校验：表达式重算、应用题交叉验证、按归因的可计算规则检查。
5. Markdown 作为内容格式，HTML 作为最终渲染结果，LaTeX 负责数学公式，SVG 负责图形。
6. 掌握度属于“错误归因 + 知识点”，而不是单独某道原题。
7. 动工前先做识别验证实验，用真实照片确认视觉模型和变式题校验达到可用水平。
8. 题目预生成进题池，孩子练习时不等待 AI。
9. 第一版先支持输入最终答案，手写答案识别放到后续版本。
10. 先实现完整的内部闭环，再优化界面和游戏化效果。
